** Ansible
   I used ansible to install Gitea.  Ansible is it's own [[file:HOWTO-ansible.org][HOWTO-ansible.org]]
   
** Install gitea via ansible role
    Using this ansible role at
    https://github.com/roles-ansible/ansible_role_gitea.  The basic
    process was:

    #+begin_example
    ansible-galaxy install do1jlr.gitea
    ansible-playbook -i hosts.txt gitea.yaml
    #+end_example

    Where hosts.txt contained the name of the system on which to
    install gitea.
** Ansible configuration
*** Files
    =/etc/gitea/gitea.ini= - the main config file
*** Users - Unix Users
    - "gitea" - user created by role for use by the daemon
    - "git" - user created by role for use with git
** Configuring gitea
*** Adding gitea users

    List users with
    =sudo -u gitea gitea -c /etc/gitea/gitea.ini admin user list=

    Add users with
    =sudo -u gitea gitea -c /etc/gitea/gitea.ini admin user create ...=
*** Starting and stopping
    Start and stop gitea thusly...
    #+begin_example
    sudo systemctl status gitea
    sudo systemctl start gitea
    sudo systemctl stop gitea
    #+end_example

*** Moving default locations
  Note above that I moved a few of the default locations to
  =/data/gitea/*= to

  1. To minimize updates and data storage on the raspberry pi's microSD
    card
     + limited writes, and I've already lost the system to bitrot/power spikes once
  2. Increase capacity
     + to a whopping huge 16GB, but it could easily be a multi-TB
       device if I ever write that much code :-)

    git clone ssh://gitea@hangout.home.port111.com:2222/gmj/test.git

**** Adding and pushing a new

     I was then able to add a new repo as
     
     #+begin_example
     mkdir new-repo
     cd new-repo
     git init .
     echo FOO >> foo.txt
     git add foobar.txt 
     git commit -mtest
     git remote add hangout ssh://gitea@hangout.home.port111.com:2222/gmj/new-repo.git
     git push --set-upstream hangout master
     #+end_example


     Note this only works if you add
     
     =ENABLE_PUSH_CREATE_USER = true=

     to the gitea.ini

*** Some notes about ports and domain names
    I'm playing games with the domain name for local testing that I
    hope will work when I make this public:

    - port111.com :: I am parking everything under =port111.com=, which
      is a public domain name I own.   This avoids conflicts with
      other uses of .local or having some fake domain (.e.g. .home)
      that is actually registered resolve if queries go beyond the
      local nameservers.

    - home.port111.com :: I am using a local https://pi-hole.net/ to
      actually serve up *.home.port111.com within my local network.
      Globally, at present, they will return NXDOMAAIN records.

    - Adding a public CNAME :: The plan is to put this up publicly, at which point I will add a
      public DNS record (probably a CNAME) pointing where this lives
